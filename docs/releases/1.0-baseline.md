This document describes what PGWhite **1.0** was at the foundation commit above. It is not updated to track later milestones.

---

## Product capability (what users/admins can do)

### Productized UI (shipping)

- Homepage **Tag / Filter → Result** retrieval
- Facets: authors, books, characters, times (场景时间), themes, devices (修辞), full-text search
- Language switching (`zh` / `en`) with existing INNER JOIN behavior for translations
- Pagination / sorting as implemented in the Nuxt app

### Admin / offline ingestion (working, not a user-facing Import UI)

- Curated corpus via local `pgwhite_testing_data.sql` (gitignored) and `data/*.json` heritage
- WeRead highlights via `scripts/generate-weread-*.mjs` → `pgwhite_weread_import.sql` → **manual** SQL apply
- Not an in-app “Import to My Library” product flow

### Engineering / R&D foundation (present, not full product UX)

- Versioned migrations `0001`–`0005` + `scripts/migrate.mjs`
- `users`, `library_entries`, `imports`, `import_items`
- Reconstructed historical WeRead Import + Daniel Library membership (quotes 119–1287)
- Gated `/api/dev/*` proof APIs (`DEV_DATA_TOOLS`; off in production by default)
- Unit tests + `pnpm typecheck` / `pnpm build`

**Do not claim** that the future user-facing WeRead → Import → My Library → Result vertical slice already exists in 1.0 UI.

## Known limitations (1.0)

- No end-user auth; seed users are R&D identity only
- No live in-app WeRead ingestion
- No Favorites
- No Global vs My Library Result scope UI
- No AI annotation product
- No publish / contribution / voting
- Historical WeRead timestamps (`createTime`) existed in API responses but were not persisted into SQL quotes
- WeRead-origin quotes generally lack curated tags/characters
- `/api/dev/*` must remain disabled in ordinary production deployments
