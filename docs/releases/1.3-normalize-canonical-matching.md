# PGWhite 1.3 — Normalize + Canonical Matching

**Status:** Accepted / finalized (`v1.3`)  
**Date:** 2026-10-03  
**Branch:** `feature/1.3-normalize-canonical-matching`  
**Migration:** `0006_canonical_matching_and_personal_layer.sql`

## Goal

Detect **relationships** between Personal imported Quotes and existing Community Quotes, derive **publication eligibility**, and preserve every Personal artifact.

**Dedup ≠ Merge.** Matching never replaces, overwrites, deletes, or auto-publishes.

## Semantics

| Matcher result | Personal Quote | Community Quote | Publication eligibility |
|----------------|----------------|-----------------|-------------------------|
| MATCHED | kept intact | kept intact | `personal_only` (no Publish Quote; future Contribute possible) |
| POSSIBLE_MATCH | kept intact | kept intact | `publication_unresolved` |
| NO_MATCH | kept intact | n/a | `publication_eligible` (still requires explicit user publish later) |

Matcher output is **not** user consent.

## Schema (additive)

- `quotes.corpus_layer` — `personal` | `community` (backfill: 1–118 community; rest personal)
- `quotes.source_chapter_uid` — WeRead chapterUid (source identity, not cross-edition canonical)
- `quotes.chapter_title` — display metadata when available
- `quotes.publication_eligibility` — matcher-derived; nullable for legacy
- `quote_match_relations` — Personal → Community relationship rows + scores
- `personal_annotations` — Personal notes on `library_entries` (matched WeRead reviews)

## Matcher v1 rules

Structural: same Book; chapter blocks only when **both** sides have non-null source chapter ids and they differ.

Targets: Community layer only.

- **MATCHED:** `matchingNormalize` exact equality only
- **POSSIBLE_MATCH:** containment / near-exact bands (ranking; never auto-MATCHED)
- **NO_MATCH:** otherwise → `publication_eligible`

Normalization: Unicode NFC, width, whitespace/newlines, outer quotes. Does **not** strip Chinese punctuation. Does **not** alter stored text.

**Provisional note:** containment with shorter-side length ≥ 4 may be overly permissive for very short Chinese Quotes. Because POSSIBLE_MATCH performs no merge/publication/deletion, 1.3 keeps this band as-is. It **requires calibration** against future real cross-edition WeRead pairs before any tightening for production UX.

## Import path

Runtime WeRead import creates Personal Quotes with chapter fields, runs matcher, stores relations/eligibility, and writes Personal annotations for associated reviews. ImportItem `raw_payload` unchanged (lossless).

## Historical data

- Curated 1–118, reconstructed Import #2, Import #3 preserved
- Chapter backfill for Import #3 bookmark items (110/120)
- No destructive rewrite of orphan-review Quotes
- Matcher relations not backfilled onto historical rows (new imports only)

## Deferred decisions (accepted for 1.3 close)

1. **No historical matcher backfill** — do not run canonical matching over existing Personal Quotes in 1.3; preserve as-is (relations created on new imports only).
2. **POSSIBLE_MATCH rules remain provisional** — especially containment shorter ≥ 4; calibrate later with real cross-edition data; do not tune arbitrarily in 1.3.
3. **Result Personal/Community scoping** — deferred to **1.5**.
4. **Publish vs Contribute UX** — deferred (model allows the distinction; no UI in 1.3).
5. **Legacy 1.2 orphan-review Quotes** — do **not** destructively migrate; keep documented debt.

## Out of scope

Publish/Contribute UI, Result Personal/Community visual split, Work→Edition, embeddings, moderation, 1.4 AI annotation.
