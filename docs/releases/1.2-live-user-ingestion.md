# PGWhite 1.2 — Live User Ingestion

**Status:** Accepted (production validation Import #3)  
**Branch:** `feature/1.2-live-user-ingestion`  
**Date:** 2026-09-30 (validation completed; Import #3 timestamps UTC 2026-10-01)

This milestone turns the offline / admin WeRead path into an application-level **user import** path for the R&D Daniel account. It does **not** add canonical deduplication, AI annotation, Global/My Result scoping, authentication, Favorite, or legacy 1169 retirement.

---

## Goal

Real user-facing WeRead ingestion from API key to PGWhite Library / Result:

```text
API Key → Notebook Discovery → Book Picker → Import Selected → Result
```

---

## User flow

1. Open `/import`
2. Paste WeRead Agent Gateway API key (request-scoped only)
3. Load notebooks via `POST /api/weread/notebooks`
4. Select one or more books in the Book Picker
5. Run `POST /api/weread/import`
6. Inspect Import result counters and per-book quote counts
7. Follow **View in Result** → `/?books=<pgBookId>`

---

## Book Picker

Displays available WeRead notebooks with:

- cover
- title
- author
- reading progress percentage
- note count

## Import semantics

### Runtime Import

- Creates one `imports` row with `source = 'weread'`, `provenance_type = 'runtime'`, `reconstruction_key = NULL`
- Status lifecycle: `processing` → `completed` (or failed counters if items fail)

### ImportItems

- One ImportItem per observed upstream highlight or review
- External ID namespaces:
  - `weread:bookmark:<bookmarkId>`
  - `weread:review:<reviewId>`
- `raw_payload` preserves upstream item data (plus association metadata for matched reviews)
- Statuses used: `processed` (success), `partial` (empty orphan review), `failed` / `duplicate` as applicable

### Dual provenance invariant

For every successful item that creates or links a LibraryEntry:

```text
Import → ImportItem → LibraryEntry
AND
LibraryEntry.import_id → same Import
```

Both pointers must agree. Multiple ImportItems may intentionally share one LibraryEntry when a review associates to an existing highlight.

### Highlights + personal annotations

- Bookmarks / highlights become Quotes (`markText`)
- Reviews / annotations are always ImportItems
- Exact structural association key: `bookId|chapterUid|range`
- Matched review → same LibraryEntry / Quote as the highlight (no second Quote)
- Unmatched review with content → own Quote (content, else abstract)
- Unmatched review with empty content → `partial` (no Quote)

### Deterministic Author / Book reuse

- Author: exact `author_translations.name` match (`zh`)
- Book: exact `book_translations.title` + `author_id` match (`zh`)
- **No** fuzzy / canonical matching in 1.2

### Why 123 ImportItems → 120 Quotes

| Kind | Count | Quote effect |
|------|------:|--------------|
| Bookmark / highlight ImportItems | 110 | 110 Quotes |
| Review ImportItems matched to a highlight (`bookId\|chapterUid\|range`) | 3 | **0** new Quotes (share highlight Quote) |

| Empty orphan / partial | 0 | — |
| **Total ImportItems** | **123** | |
| **Distinct Quotes** | | **120** |

Difference of **3** is exactly the three matched review → highlight associations. Provenance invariant violations on Import #3: **0**.

Book **5** was **reused** via exact title+author match (pre-existing metadata / historical quotes). Import #3’s 93 Quotes did not replace the historical reconstructed set. Book **20** was created for this import (27 Quotes, all from Import #3).

Legacy reconstructed Import `#2` (`legacy_weread_batch_2026-07-26`, 1169 Library Entries, quotes 119–1287) remained intact — this validation did not delete or rewrite it.
