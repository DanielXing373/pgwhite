### Observations

- **Duplicates/synonyms:** No exact duplicates. Soft near-neighbors: 痛苦/厌恶; 末日/死亡; 轮回/命运 — distinct enough for humans, blurry for embeddings.
- **Suspicious / broad:** **时间** is the only high-volume theme and collides conceptually with Scene/Time (`source_code=1`: 黄昏/正午/深夜/日出/暴风雨). Risk: free “时间感” concepts reconcile to Theme 时间 or to a Scene/Time tag depending on candidate set.
- **Very few assignments:** 11/13 themes have exactly 2 assignments (likely paired EN+ZH or twin quotes) — poor centroid stability for embedding targets.
- **Reconciliation fitness:** **Marginal.** Useful as a small closed set for “Existing Assignment” demos; expect high Personal-concept rate if free generation is rich/high-recall. **Do not treat as a complete literary theme ontology.**

### Observations

- **Duplicates/synonyms:** 隐喻 / 内涵 / 意象 frequently co-assigned (pairs of 6). For Chinese literary tagging these overlap; embeddings will struggle to separate them.
- **Suspicious / broad:** 内涵, 意象, 长句描写 are catch-alls; 隐喻 is over-applied (default device).

Scene/Time (`source_code=1`, 5 tags, 26 assignments) audited only for collision awareness — **not** an active v1 generation dimension.

## 7. Proposed Workbench architecture

Research-only tree: `research/annotation-workbench/` (mirrors 1.3 dedup harness).

```text
research/annotation-workbench/
  README.md
  src/
    safety.ts              # block non-SELECT SQL; ban persistImport
    types.ts               # fixture, run, concepts, eval
    taxonomySnapshot.ts    # read-only dump of Theme/Device tags
    adapters/
      llm.ts               # LLMAdapter interface
      embedding.ts         # EmbeddingAdapter + BGE-M3 / Qwen3 stubs
    pipeline/
      freeConcepts.ts      # Quote (+ optional annotation) → raw concepts
      interpretAnnotation.ts
      reconcile.ts         # concepts × taxonomy embeddings → assignment | personal
    eval/
      rubric.ts            # Useful / Okay / Bad + issue flags
  fixtures/                # NOT FINALIZED — await product decisions
  runs/<run_id>/           # immutable per-run JSON (gitignored or local)
  review/index.html        # local visual compare (not production UX)
  scripts/
    export-readonly-snapshot.mjs
```

### Run record (immutable per `run_id`)

- `fixture_version`, `taxonomy_version`, `prompt_version`
- `llm` model/version, `embedding` model/version
- per quote: raw free concepts; top-k reconcile candidates + similarity scores; final Existing Assignments; proposed Personal concepts; annotation interpretation `{tag_signal|reflective_note|mixed|unclear}`
- human eval overlay (does not overwrite model outputs)

### Human evaluation (minimum)

- Overall: Useful / Okay / Bad  
- Flags: Missing useful tag · Too many tags · Bad interpretation · Wrong rhetorical device · Bad taxonomy match · Good new concept  

### Invariants enforced by Workbench

- No production DB writes; no `quote_tags` mutation; no taxonomy expansion; no Quote/annotation text changes  
- Multiple `run_id`s comparable side-by-side  
- Similarity = retrieval signal, not “correct interpretation” probability

## 8. How BGE-M3 and Qwen3-Embedding plug in

```ts
interface EmbeddingAdapter {
  id: 'bge-m3' | 'qwen3-embedding' | string
  embed(texts: string[]): Promise<number[][]>
}
```

1. Snapshot taxonomy labels (zh primary; optional en) → embed once per `(embedding_id, taxonomy_version)`.
2. For each free concept string → embed → cosine top-k against Theme set and Device set **separately** (dimension-aware).
3. Record scores; apply **experiment-only** threshold (not production). Below threshold → Personal concept.
4. Same fixture + same LLM free concepts can be re-reconciled under BGE-M3 vs Qwen3 as two `run_id`s (or shared free-concept stage + two reconcile stages).

**No winner, no production threshold** until Chinese PGWhite empirical runs exist.

## 9. Repository / schema conflicts (summary)

1. **Annotation evidence gap** for Import #3 vs `personal_annotations` (S1).  
2. **No AI/human provenance** on `quote_tags` (S4).  
3. **Personal layer never tagged** — AI Personal tags have nowhere product-safe to land yet without new tables or Personal-scoped tag assignments.  
4. **Theme “时间” vs Scene/Time dimension** naming collision.  
5. **tagKind default** in `server/utils/tagKind.ts` falls back to column `kind` if config omitted; runtime `nuxt.config` sets `source_code` — OK in app, fragile if Workbench reads tags without the same config.  
6. **Orphan-review Quotes** pollute “literary Quote” cold-start if not filtered.  
7. **EN/ZH dual Community Quotes** share tagging patterns unevenly — ZH-only filter required.

None of these block a **research-only** Workbench that writes under `research/annotation-workbench/runs/`. All block **production** AI annotation integration.
