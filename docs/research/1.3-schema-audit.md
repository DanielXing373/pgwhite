# PGWhite 1.3 — Schema audit (pre-migration)

**Date:** 2026-10-03  
**Branch:** `feature/1.3-normalize-canonical-matching`  
**Conclusion:** Existing model supports additive evolution. Proceed with migration `0006`.

## Audit answers

1. **Personal imported Quote as own `quotes` row?**  
   Yes. 1.2 `persistImport` inserts a new `quotes` + `quote_translations` row per highlight/orphan review, then `library_entries`.

2. **Does `library_entries.quote_id` force Personal/Community to share one Quote row?**  
   No. Membership points at a Quote; Personal import creates a distinct Quote. Community curated rows (1–118) are separate. Gap: there was no `corpus_layer` column — Result treated all Quotes as one shared corpus.

3. **Where Personal vs Community scope lives?**  
   Additive: `quotes.corpus_layer` ENUM(`personal`,`community`).  
   Backfill: ids 1–118 → `community`; all others → `personal` (includes reconstructed WeRead + Import #3).  
   Does not move/delete rows.

4. **Canonical relationship without merging?**  
   New table `quote_match_relations` (source Personal Quote → target Community Quote, status, eligibility, features). Never updates/deletes either Quote’s text.

5. **POSSIBLE_MATCH representation?**  
   Same table with `relation_status='possible_match'`. Multiple targets allowed per source.

6. **Chapter source identity + display title?**  
   On `quotes`: `source_chapter_uid` (WeRead chapterUid — source identity, not cross-edition canonical) + `chapter_title` (human-readable when known). ImportItem `raw_payload` remains lossless backup.

7. **Personal annotations?**  
   New `personal_annotations` attached to `library_entries` (not Community Quote). Matched WeRead reviews write here. Legacy 1.2 orphan-review Quotes left untouched (documented debt).

8. **ImportItem/raw payload lossless?**  
   Yes — unchanged. Relations/annotations are additive.

9. **Existing 1.2 data?**  
   Preserved. Optional additive chapter backfill from bookmark raw_payload. No matcher rewrite of historical text. No orphan-review migration.

10. **Additive without destructive migration?**  
    Yes. ALTER ADD COLUMN + CREATE TABLE + careful backfill UPDATEs only on new nullable/defaulted columns.

## ADR note

ADR-002 previously said same canonical quote must not produce duplicate Result cards. Product 1.3 clarifies Personal and Community artifacts **coexist** and future UI may show both. ADR-002 updated accordingly — dedup ≠ merge / ≠ card collapse.

## Matcher v1 (implementation)

- Scope: same `book_id`; chapter blocks only when both sides have non-null `source_chapter_uid` and they differ.
- Targets: `corpus_layer='community'` only.
- **MATCHED:** research-normalized exact equality only → `publication_eligibility=personal_only`.
- **POSSIBLE_MATCH:** containment / high similarity bands for ranking only → `publication_unresolved` (never auto-MATCHED).
- **NO_MATCH:** no relation row; source Quote `publication_eligibility=publication_eligible`.
- Matcher never publishes, merges, or mutates Community content.
